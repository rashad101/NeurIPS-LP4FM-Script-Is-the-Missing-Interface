## Quickstart

### 1. Install

```bash
./setup_env.sh                # auto-detects CUDA; installs the matching stack
./setup_env.sh --gpu          # force torch + vLLM
./setup_env.sh --cpu          # force CPU (no vLLM) — laptop development
./setup_env.sh --with-api     # additionally install the Anthropic SDK (H5 judge)
```

`setup_env.sh` installs [uv](https://docs.astral.sh/uv/) if missing, creates
`.venv` (Python 3.11), installs the right extras, and prints a verification
report including which caches are repo-local.

### 2. Smoke test (a few minutes, CPU only, ~1 GB download)

```bash
./run.sh --smoke
```

Runs the entire pipeline on 8 items with a 0.5B model. Use this to confirm the
plumbing before spending GPU time.

### 3. Calibrate the transforms against real data (recommended)

```bash
source .venv/bin/activate
scriptgap download --dakshina    # ~2 GB read, ~29 MB kept
scriptgap calibrate              # fits the noise operators to attested romanisation
```

Skipping this leaves the condition-3 probabilities hand-set, which the
measurement below shows are wrong by up to 7×. See
[`scriptgap calibrate`](#scriptgap-calibrate).

### 4. Authenticate for the real datasets and models

```bash
source .venv/bin/activate
hf auth login                 # MILU, Llama and Gemma are gated
export ANTHROPIC_API_KEY=...  # only for the H5 judge
```

### 5. Full run

```bash
# Fits one GPU-day (~18k generations across 5 models, 3 of them Indic-specialised)
./run.sh -c configs/models.yaml -c configs/budget.yaml --max-seconds 36000

# Or the larger default configuration (~43k generations across 6 models)
./run.sh
```

If the time budget is hit, the run exits with code 2 and prints the resume
command. Nothing is lost.

## The five conditions

The paper's §2 taxonomy of orthographic variation, plus the native baseline.
Every item is rendered in all five, so orthography is the only thing that
varies.

| # | Condition | What it is | Samples |
|---|---|---|---|
| 1 | `native` | Gold native-script item, untouched | 1 |
| 2 | `clean_roman` | Scheme-based transliteration (Aksharamukha, ISO-15919, de-diacriticised to a keyboard-typable form) | 1 |
| 3 | `noisy_roman` | Ad-hoc romanisation: schwa deletion, long/short vowel collapse, gemination collapse, aspiration drop, sibilant swap, SMS-isms, transposition | 3 |
| 4 | `native_noisy` | **Script-internal** noise: dropped/swapped matras, lost nuktas, anusvara↔candrabindu confusion, dropped virama | 3 |
| 5 | `codemix` | Matrix Indic language + English content-word insertion, subject to the free-morpheme constraint | 1 |

Condition 4 is what makes the causal claim work: it isolates "misspelled" from
"different script", so a drop on condition 3 cannot be dismissed as generic
typo-robustness. Conditions 3 and 4 are stochastic, so they are sampled
`data.noisy_samples` times (default 3) with a seeded per-cell RNG — any single
cell can be regenerated byte-identically.

Condition-3 probabilities in `configs/default.yaml` are **fitted, not hand-set**
— measured against Dakshina's native-speaker romanisations and stored
per-language, because the attested rates differ by up to 35× across languages
(see [`scriptgap calibrate`](#scriptgap-calibrate)). Precedence is
`--set` > per-language > global, so a sensitivity sweep still works. Condition 4
is *not* fitted; there is no comparable corpus of attested native-script
misspellings. The effective probabilities are recorded per language in each
run's `suite_manifest.json`.

### Plus an opt-in sixth: `attested_roman`

Conditions 2–5 are *generated*. The obvious objection is **"you measured your
own noise model, not what users type."** So there is a sixth condition backed by
real data:

| # | Condition | What it is | Samples |
|---|---|---|---|
| 6 | `attested_roman` | Each native word replaced by a **native-speaker romanisation sampled from Dakshina**, count-weighted; scheme transliteration only as a fallback for out-of-lexicon words | 3 |

```bash
scriptgap download --dakshina                       # ~2 GB read, ~29 MB kept
scriptgap build-data --set data.dakshina.enabled=true --force
```

It is deliberately **not** in `CONDITIONS`, so the paper's "five orthographic
renderings" still describes the released suite exactly. Its job is validation:
`summary.json:synthetic_vs_attested` reports how far the rule-generated register
(condition 3) is from the attested one, per cell and in correlation. Every
attested cell also carries `attested_coverage` — the fraction of word tokens that
came from real human data rather than the fallback — so results can be
conditioned on it.

Dakshina is also what makes the operator probabilities empirical rather than
hand-set; see [`scriptgap calibrate`](#scriptgap-calibrate).

### Self-containment

`src/scriptgap/env.py` runs on import and redirects `HF_HOME`,
`HF_DATASETS_CACHE`, `TORCH_HOME`, `VLLM_CACHE_ROOT`, `TRITON_CACHE_DIR`,
`TIKTOKEN_CACHE_DIR`, `MPLCONFIGDIR`, `XDG_CACHE_HOME` and `TMPDIR` into
`.cache/`. `setup_env.sh` and `run.sh` export the same variables so
subprocesses that never import the package (vLLM workers, `uv`) are covered
too. Model weights are fetched with `snapshot_download(local_dir=...)` into
`models/<name>/`, and backends load from that directory when it exists.

Pre-existing values are respected, so exporting `HF_HOME` yourself to share a
large weight cache between checkouts still works.

Verify at any time:

```bash
python -c "from scriptgap import env; [print(f'{k:24} {v}') for k,v in env.describe().items()]"
```

## Commands

All stages are subcommands of `scriptgap` (equivalently
`python -m scriptgap.cli`). Common flags:

| Flag | Meaning |
|---|---|
| `-c PATH` | Layer another YAML config over `configs/default.yaml` (repeatable) |
| `--set a.b.c=VALUE` | Dotted-key override, YAML-parsed (repeatable). Beats per-language defaults. |
| `--run-id ID` | Reuse a run directory; `latest` for the most recent |
| `--run-prefix NAME` | Label a new timestamped run (`ablation-20260730-141205`) |
| `--log-level LEVEL` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `--no-progress` | Disable progress bars (cron/CI) |

### `scriptgap download`

Prefetch weights into `models/` and datasets into `.cache/huggingface`.

```bash
scriptgap download -c configs/models.yaml
scriptgap download -c configs/models.yaml --model sarvam-m --force
scriptgap download --skip-models          # datasets only
```

### `scriptgap calibrate`

Fit the condition-3 operator probabilities to attested human romanisation
instead of hand-setting them (spec §4 asks for exactly this).

```bash
scriptgap download --dakshina        # once: ~2 GB read, ~29 MB kept
scriptgap calibrate                  # measures rates over all suite languages
scriptgap build-data -c data/calibration/noisy_roman.yaml --force
```

Writes `data/calibration/dakshina_rates.json` (full per-language measurement)
and `data/calibration/noisy_roman.yaml` (a layerable config fragment). Both are
copied into the run's `metrics/calibration.json` for provenance.

**The measured result, on all five suite languages** (37 lexicons, 27,500 native
words per language, 48k–99k attested romanisations each):

| operator | configured | attested (pooled) | per-language spread |
|---|---|---|---|
| `schwa_deletion` | 0.350 | **0.052** | 0.007 – 0.116 (16.6×) |
| `vowel_ending_drop` | 0.200 | **0.353** | 0.015 – 0.536 (35.7×) |
| `gemination_collapse` | 0.600 | **0.294** | 0.096 – 0.408 (4.2×) |
| `long_vowel_collapse` | 0.550 | **0.356** | 0.000 – 0.441 |
| `sibilant_swap` | 0.200 | **0.179** | 0.038 – 0.340 (8.9×) |
| `aspiration_drop` | 0.150 | **0.038** | 0.010 – 0.092 (9.2×) |

Two things follow, and both are reportable:

1. **The hand-set defaults were wrong**, mostly too aggressive — schwa deletion
   by 7×. An uncalibrated condition 3 would have overstated the H3 gap. What the
   defaults modelled as word-internal schwa deletion is in reality dominated by
   the *word-final* case, which is why `vowel_ending_drop` is the one operator
   set too low.
2. **The rates are not uniform across languages** — final-vowel dropping runs at
   0.54 in Hindi and 0.02 in Telugu. So the operators are **per-language**
   (`transforms.noisy_roman_by_language`), falling back to the pooled block.
   A single global set would inject Hindi-shaped noise into Telugu items and
   inflate that language's gap with spellings no Telugu speaker produces.

### `scriptgap build-data`

Build native-script base items, then render all five conditions.


Two resumable stages: `data/suite/base.jsonl` (slow, network-bound; reused

### `scriptgap export` / `scriptgap verify-export`

Bundle a run into a self-contained, checksummed archive. `runs/` is gitignored,
so results otherwise live only on one machine's disk.

```bash
scriptgap export --run-id latest                  # -> exports/scriptgap_<run>.tar.gz
scriptgap export --run-id latest --no-compress    # leave a directory
scriptgap verify-export exports/<run>             # re-check every checksum
```

The bundle contains the parquet (prompts and completions included), every
prediction shard verbatim, the rendered suite, metrics, figures, logs, the run
manifest, the calibration measurement, the human-review sheets, and `EXPORT.json`
with a SHA-256 per file plus a **completeness report** — shards without a `.done`
marker are listed, so a partial run cannot be mistaken for a finished one.

**Raw safety completions are excluded by default.** `--include-raw` adds them and
logs a warning; do not distribute the result.

### `scriptgap all` / `scriptgap list-runs`

```bash
scriptgap all -c configs/models.yaml -c configs/budget.yaml --skip-decompose
scriptgap list-runs
```

### `run.sh`

Wraps the above with the repo-local cache environment and a shared run id.

```bash
./run.sh                                     # full pipeline, fresh run
./run.sh --smoke                              # tiny CPU check
./run.sh --resume latest                      # continue the most recent run
./run.sh --stage inference --resume 20260730-141205
./run.sh --model sarvam-m --task milu
./run.sh --max-seconds 36000 --skip-decompose
./run.sh --theme dark --stage figures
./run.sh --stage calibrate                    # fit operators to Dakshina
./run.sh --stage export                       # archive an existing run
./run.sh --no-export                          # skip the final archive step
./run.sh --setup                              # re-install deps first (see below)
```

`--stage` accepts: `download calibrate build-data inference decompose fertility
metrics figures export all`. The `all` pipeline archives the run as its last
step, so results survive losing the machine; `--no-export` skips it.

**`run.sh` does not install dependencies.** `setup_env.sh` re-resolves the whole
dependency set and then verifies it by importing torch and vLLM, which costs a
minute or more and changes nothing once `.venv` exists. Run it when the
environment actually needs to change — a fresh clone, or after editing
`pyproject.toml`:

```bash
./setup_env.sh --with-api      # or: ./run.sh --setup
```

If `.venv` is missing, `run.sh` says so and stops rather than guessing.
`--no-setup` is still accepted, and is now a no-op.

## Experiment recipes (H1–H6)

| Hypothesis | What it needs | Where the number lands |
|---|---|---|
| **H1** gap is consistent across tasks and models | full inference | `gaps.csv`, `summary.json:h1_mean_gap_by_condition`, figure 1 |
| **H2** Indic specialisation does not *reliably* close the gap | ≥ 2 models with `role: indic-specialised` | `h2_variance.csv`, `summary.json:h2_specialised_gap_spread` |
| **H3** ad-hoc romanisation hurts more than clean transliteration | conditions 2 and 3 | `h3_clean_vs_noisy.csv`, figure 2 |
| **H4** refusal degrades under romanisation/code-mixing | `data.safety.enabled: true` | `h4_refusal.csv`, figure 3 |
| **H5** failures are substantially *understand-but-fail-to-act* | `scriptgap decompose` | `h5_decomposition.csv`, figure 4 |
| **H6** the preferred register is cheaper to serve | `scriptgap fertility` | `h6_fertility.csv`, figure 5 |

**H2 is a variance claim, not a failure claim.** The metrics stage computes the
gap spread *among Indic-specialised models only* (`role` containing `indic` in
`configs/models.yaml`) and warns if fewer than two are present. A specialised
model that does well on one register while gapping on another **supports** H2 —
the loop diagnosis predicts high variance, not uniform failure.

Selected recipes:

```bash
# H1/H2 headline: all models, MCQ + math, native vs the two roman conditions
./run.sh -c configs/models.yaml -c configs/budget.yaml \
         --task milu --task math \
         --condition native --condition clean_roman --condition noisy_roman

# H3 only, one model, fast
scriptgap run-inference -c configs/models.yaml --model qwen3-8b \
  --condition native --condition clean_roman --condition noisy_roman

# H4 safety sweep (aggregate reporting only)
scriptgap run-inference -c configs/models.yaml --task safety
scriptgap metrics && scriptgap figures

# H6 alone — no GPU needed
scriptgap fertility -c configs/models.yaml --run-id latest

# Universality sidebar (figure 6)
scriptgap build-data --set data.arabizi.enabled=true --force
scriptgap run-inference -c configs/models.yaml --task arabizi

# Validate the synthetic register against attested human romanisation
scriptgap download --dakshina
scriptgap calibrate
scriptgap build-data -c data/calibration/noisy_roman.yaml \
  --set data.dakshina.enabled=true --force
./run.sh -c configs/models.yaml -c configs/budget.yaml \
         -c data/calibration/noisy_roman.yaml \
         --set data.dakshina.enabled=true
# -> summary.json:synthetic_vs_attested

# Sensitivity: how much of the gap is the noise level?
# `--set` beats the per-language calibrated defaults, so this applies to every
# language (without that precedence rule it would be a no-op for exactly the
# five languages the suite uses).
scriptgap build-data --run-prefix noise-low \
  --set transforms.noisy_roman.schwa_deletion=0.15 \
  --set transforms.noisy_roman.long_vowel_collapse=0.25 --force
```

## Planning the compute

Cells per item = `5 conditions + (noisy_samples − 1) × 2 stochastic conditions`.

| Config | Items | Cells/item | Per model | Models | Generations |
|---|---|---|---|---|---|
| `budget.yaml` | 520 | 7 | 3,640 | 5 | **18,200** |
| `default.yaml` | 800 | 9 | 7,200 | 6 | **43,200** |
| `smoke.yaml` | 8 | 5 | 40 | 1 | 40 |

Enabling `attested_roman` adds `noisy_samples` more cells per item (+3 on
default, +2 on budget).

`budget.yaml` pins the roster to five models — one generalist, one multilingual
generalist, and **three** Indic-specialised. Item counts are sized down so the
third specialised model fits inside the same 18,200 budget: H2 is a variance
claim, and a spread estimated from two points is not worth the GPU time. Layer it
*after* `models.yaml` (`-c configs/models.yaml -c configs/budget.yaml`) — a
`models:` list replaces rather than merges, which is what makes this work.

Knobs, in order of effect: `--model` (run models in separate passes),
`data.noisy_samples`, `data.*.n_per_language`, and
`inference.max_new_tokens.*` — the math and IFEval budgets dominate wall-clock,
not the MCQ ones.

### 48 GB memory notes

See [GPU memory: one model at a time](#gpu-memory-one-model-at-a-time) for how
sequencing and teardown work.

| Model | bf16 weights | On 48 GB |
|---|---|---|
| Llama-3.1-8B, Qwen3-8B, Airavata-7B | ~14–16 GB | comfortable |
| Gemma-3-12B | ~24 GB | comfortable |
| Nanda-10B | ~20 GB | comfortable |
| **Sarvam-M (24B)** | **~48 GB** | **does not fit in bf16** — ships with `quantization: fp8` in `configs/models.yaml` |

If vLLM reports insufficient KV cache, lower
`inference.vllm.gpu_memory_utilization` or `max_model_len`:

```bash
scriptgap run-inference -c configs/models.yaml \
  --set inference.vllm.gpu_memory_utilization=0.85 \
  --set inference.vllm.max_model_len=2048
```

## GPU memory: one model at a time

**Only one model is ever resident.** The roster is walked sequentially: build a
backend, run every shard for that model, tear it down, verify the card is free,
then load the next. That is what lets a 24 GB fp8 Sarvam-M and a 24 GB Gemma-3
share one 48 GB card in a single pass.

```
=== model 1/5: llama-3.1-8b-instruct (generalist / vllm) ===
before loading llama-3.1-8b-instruct   gpu0 (A100): 47.2/48.0 GiB free (98%)
after  loading llama-3.1-8b-instruct   gpu0 (A100): 30.1/48.0 GiB free (63%)
...
unloaded llama-3.1-8b-instruct         gpu0 (A100): 47.0/48.0 GiB free (98%) (reclaimed +16.9 GiB)
=== model 2/5: gemma-3-12b-it (generalist / vllm) ===
```

Sequencing alone is not sufficient, so three further things happen.

**Teardown drops every reference, not just the obvious one.** `del llm` frees one
handle; vLLM also keeps an executor holding the weights and KV cache,
module-level distributed state, and a tokenizer that can back-reference the
engine. `models/gpu.py` drops each explicitly, calls
`destroy_model_parallel()` / `destroy_distributed_environment()`, tears down the
process group, collects twice, and empties the allocator cache. Each step is
attempted independently so a renamed internal in a newer vLLM cannot block the
others.

**The result is verified, not assumed.** Free VRAM is read from the driver via
`torch.cuda.mem_get_info` — not `memory_allocated`, which only sees this
process's tensors and would miss a KV cache that was never handed back. The
driver polls until the card is at least `inference.min_free_fraction` free
(default 0.80) and **warns loudly** if it is not, naming the fix. A teardown that
silently fails is worse than one that errors: the next model OOMs and nothing
points at the cause.

**Process isolation is the guarantee.** In-process cleanup is best-effort — the
CUDA context itself is not always returned. `inference.isolate_models` runs each
model in a child process, so the OS reclaims everything on exit:

| Value | Behaviour |
|---|---|
| `auto` (default) | A child process per model when the backend is vLLM **and** there is more than one model. A single model has nothing to protect against; `hf` and `anthropic` release cleanly. |
| `always` | One process per model, unconditionally. Use this if you ever see the not-fully-released warning. |
| `never` | In-process teardown only. |

This is safe because every shard is checkpointed: the child writes into the same
`runs/<run_id>/` tree, and a child that dies mid-shard leaves a resumable partial
shard exactly as an in-process crash would.

**One model failing does not cost the rest.** On an unattended multi-hour run, a
model that OOMs or has missing weights is logged, recorded in
`summary["failed_models"]`, and the roster continues; its shards stay
checkpointed for a later resume. Set `inference.continue_on_model_error: false`
to make the first failure fatal instead.

```bash
# force per-model process isolation
scriptgap run-inference -c configs/models.yaml \
  --set inference.isolate_models=always

# or run one model per invocation yourself — equivalent, and easiest to babysit
for m in llama-3.1-8b-instruct sarvam-m airavata-7b; do
  scriptgap run-inference -c configs/models.yaml --run-id myrun --model "$m"
done
```

## Runs: separability and resume

Runs are separable **by time** and **by algorithm**, as the plan requires.

```
runs/<run_id>/
  manifest.json                              config + git sha + GPU/env snapshot, per stage
  logs/<stage>.log                           one file per stage
  predictions/inference/<model>/<task>__<lang>__<condition>.jsonl
  predictions/inference/<model>/<...>.jsonl.done   completion marker
  predictions/decompose/<model>/failures.jsonl
  predictions/fertility/<tokeniser>/pairs.jsonl
  raw/safety/<model>/<...>.jsonl             full safety completions (gitignored)
  metrics/script_gap_results.parquet         the released long-format table
  metrics/*.csv  metrics/summary.json
  figures/*.pdf  figures/*.png
```

- **By time** — the default `run_id` is a UTC timestamp, so `runs/` sorts
  chronologically. `--run-prefix ablation` gives `ablation-20260730-141205`.
- **By algorithm** — one directory per model, one shard per
  `task__language__condition`. Delete a shard and re-run to regenerate only
  that cell; add a condition later without touching the rest.

### Resume semantics

Predictions are appended and flushed (with `fsync`) every
`inference.checkpoint_every` generations, in chunks of
`inference.vllm.chunk_size`. On restart:

1. A torn final line from a `kill -9` is detected and truncated — earlier
   records survive.
2. The shard's existing `uid`s are read and those items skipped.
3. Shards carrying a `.done` marker are skipped without being parsed.

Both paths are exercised by `tests/test_checkpoint.py` and were verified
end-to-end:

```
# full resume — nothing regenerated
shard qwen2.5-0.5b-instruct/math__bn__native already complete — skipping
model qwen2.5-0.5b-instruct totals: {'generated': 0, 'skipped': 40}
```

## What gets saved, and why

Every prediction record is **self-contained** — re-analysis never has to
reconstruct the prompt by joining against a suite file that may since have been
rebuilt:

| Field | Why it is there |
|---|---|
| `prompt`, `options`, `response` | The actual text sent and returned. Without these the released table is a scoreboard, not a re-analysable result. |
| `prompt_sha256` | Content hash of the prompt+options. See the staleness guard below. |
| `finish_reason`, `truncated`, `output_tokens` | A generation cut off at `max_tokens` is indistinguishable from a wrong answer once reduced to a score. |
| `gold`, `parsed`, `correct`, `parse_failed`, `detail` | Lets you re-score under a different parser without re-running the GPU. |
| `roundtrip_pass`, `transform_applied` | The gating decisions, so exclusions stay auditable and reversible. |
| `latency_s`, `response_chars`, `empty_response` | Cost and failure-mode analysis. |

All of it flows into `metrics/script_gap_results.parquet` (28 columns). Set
`metrics.include_text: false` to drop the text if file size ever becomes a
problem.

## Data sources and access

| Task | Source | Notes |
|---|---|---|
| `milu` | `ai4bharat/MILU` | **Gated** — accept the terms and `hf auth login`, or the task builds 0 items (logged, non-fatal) |
| `math` | `juletxara/mgsm` | Indic coverage is **`bn` and `te` only**. Hindi maths needs `data.math.indicgenbench.enabled=true` or your own file. |
| `ifeval` | generated by `data/ifeval.py` | 25 Hindi stems × 14 verifiable structural constraints; deterministic given the seed |
| `safety` | `DAMO-NLP-SG/MultiJail` | Indic coverage is **`bn` only**. For Hindi: `data.safety.translate_to=[hi]` (IndicTrans2, machine-translated and tagged as such) or point `data.safety.local_file` at verified translations. |
| `arabizi` | `openai/MMMLU` (`AR_XY`) | Opt-in via `data.arabizi.enabled=true` |
| `attested_roman` + calibration | [Dakshina](https://github.com/google-research-datasets/dakshina) v1.0 lexicons | Not gated. `scriptgap download --dakshina` streams the 2 GB tar and keeps only the lexicon TSVs (~29 MB, 37 files, 12 languages). Covers `bn gu hi kn ml mr pa sd si ta te ur` — all five suite languages. |

Gated **models** (Llama-3.1, Gemma-3) also need `hf auth login`; they are marked
`gated: true` in `configs/models.yaml` and the downloader prints the fix.

Upstream schemas drift, so the builders resolve columns through a candidate list
and, on failure, raise an error naming the columns they *did* find rather than
silently producing wrong gold labels.
